## [0:20 ~ 1:10] ① 문제와 LIS

[화면: ① 의 `a b c d → d a b c` 코드 블록]

목록 순서가 바뀌면 diff 는 key 로 같은 줄을 찾아 옮깁니다. 그런데 어떤 줄을 옮길지 정하는 방법이 여러 가지입니다. React 처럼 앞에서부터 보며 순서가 어긋난 줄을 옮기면, 맨 아래 줄 하나를 위로 올릴 때 나머지가 전부 "앞으로 왔다" 고 판단해서 세 줄을 다 옮깁니다.

저희는 LIS, 최장 증가 부분 수열을 썼습니다. 옛 위치가 3, 0, 1, 2 일 때 커지는 순서로 이어진 0, 1, 2 는 이미 순서가 맞으니 그대로 두고, d 하나만 옮깁니다.

[화면: ① 의 공식]

나머지는 어떤 방법으로도 한 번은 옮겨야 하니까, 남은 줄 빼기 LIS 길이가 이론상 최소입니다.

[화면: moves 그래프]

그래서 1,000줄이면 999번 대 1번, 10만 줄이면 99,999번 대 1번입니다.

## [1:10 ~ 2:20] ② 같은 LIS 라도 다르다 — 핵심

[화면: ② 첫 문단]

여기까지는 LIS 를 쓰면 누구나 얻는 결과입니다. 저희가 찾은 건 그다음입니다. 몇 번 옮길지를 줄여도, 각 줄을 몇 번째에서 몇 번째로 옮길지 계산해야 합니다. 흔한 구현은 옮길 때마다 배열에서 위치를 찾고 빼고 넣습니다. 저희 첫 구현도 그랬습니다. 한 번에 n, 그걸 n 번 하니까 n 제곱입니다.

[화면: complexity 그래프 — 빨간 선에서 초록 선으로]

빨간 선이 흔한 구현, 초록 선이 저희입니다. 로그 축이라 기울기가 곧 복잡도인데, 빨간 선이 훨씬 가파릅니다. 5만 줄을 뒤집으면 5초 걸리던 게 62밀리초, 82배 빨라졌습니다.

[화면: ② 의 좌표 그림]

방법은, 모든 줄이 최종적으로 갈 자리를 미리 좌표로 세워 두고, "지금 내 앞에 몇 개 있나" 를 Fenwick 트리로 세는 겁니다. 한 번에 log n 이라 전체가 n log n 이 됩니다.

# QnA 대비 — 20초 답변

답변 구조: **결론(5초) → 근거·수치(10초) → 한계 인정(5초)**

### Q1. LIS 는 Vue 도 쓰는데, 그럼 뭐가 다른가요? (차별점)

> 이동 횟수는 Vue 와 같은 이론상 최소입니다. 저희가 다른 건 옮길 위치를 계산하는 부분인데, 흔하게 짜는 방식은 n 제곱이라 5만 줄 뒤집기에 5초가 걸렸고, Fenwick 트리로 바꿔 62밀리초가 됐습니다. 다만 Vue 본체와 직접 시간을 비교하지는 않았습니다.

### Q2. Fenwick 트리가 뭔가요? 직접 설명해 보세요. (이해도)

> 배열의 앞부분 합을 log n 에 구하는 자료구조입니다. 모든 줄의 최종 자리를 미리 한 줄로 세워 두고, 지금 DOM 에 있는 자리는 1, 없는 자리는 0 으로 표시합니다. 그러면 "내 앞에 몇 개 있나" 가 앞부분 합이라 log n 에 나오고, 이게 곧 패치에 쓸 인덱스입니다. README ② 의 그림이 그 과정입니다.

### Q3. 실제 서비스에서 의미 있는 차이인가요? (실용성)

> 줄 하나를 위로 올리는 동작은 채팅방, 알림, 최근 항목처럼 아주 흔합니다. 1,000줄 브라우저 측정에서 28밀리초 대 4.9밀리초라, 한 프레임 16밀리초를 넘기느냐 마느냐의 차이입니다. 다만 수십 줄짜리 목록이면 둘 다 충분히 빠르고, 노트북 한 대에서 잰 값입니다.
