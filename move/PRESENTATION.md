## [0:55 ~ 1:55] diff 를 빠르게 (약 1분)

[화면: ④ 코드 블록 → stages 그래프]

그래서 배열을 노드마다 새로 만들지 않고, 하나를 덮어쓰다가 패치가 생길 때만 복사하게 바꿨습니다. 함수마다 malloc 하던 걸 스택 버퍼 하나로 바꾼 셈입니다. 모든 업데이트에서 2.1배에서 3.3배, 1만 줄을 다시 그리는 diff 가 38밀리초에서 12밀리초가 됐습니다.

[화면: ⑤ complexity 그래프]

목록 순서가 바뀔 때는 숨은 n 제곱도 있었습니다. 옮길 위치를 매번 처음부터 찾았기 때문인데, Fenwick 트리로 바꿔 5만 줄 뒤집기가 3초에서 23밀리초가 됐습니다.

★ [화면: ⑥ moves 그래프] 옮기는 횟수 자체도 LIS 로 이론상 최소라, 1,000줄이면 999번 대 1번입니다.

[화면: ⑦ 과제 요구사항 문장]

과제의 뒤로가기, 앞으로가기는 이동할 때마다 diff 를 했고, 기록마다 화면 트리 전체를 저장했습니다.

[화면: ⑦ 코드 블록 — 키프레임 그림]

이걸 동영상 코덱처럼 바꿨습니다. 10칸마다 화면 트리 하나를 키프레임으로 두고, 그 사이는 앞뒤로 가는 패치만 저장합니다. 한 칸 이동은 저장된 패치를 그대로 쓰니 diff 가 0번입니다.

[화면: ⑦ history 그래프 → 표]

기록 메모리는 207메가에서 23메가, 한 칸 뒤로가기는 0.003밀리초가 됐습니다. 그리고 실제 영역을 다시 그리지 않고 패치만 하니까, 이동해도 입력하던 값과 포커스가 그대로 남습니다.

★ 대신 기록할 때 뒤로 가는 패치를 만드느라 1밀리초 정도 느려지는 대가가 있습니다.

# 1분 Q&A 방어 족보 — 핵심 4대 질문

답변 구조: **결론(5초) → 근거 · 수치(10초) → 한계 인정(5초)**

### Q1. 뒤로가기 · 앞으로가기는 다른 팀도 다 만들었을 텐데, 뭐가 다른가요? (차별점)

> 기능은 같지만 방식이 다릅니다. 보통은 기록마다 화면을 통째로 저장하고 이동할 때 다시 비교하는데, 저희는 키프레임 사이를 패치로만 저장해서 메모리가 9분의 1이고, 한 칸 이동에는 diff 를 하지 않습니다. 실제 영역을 다시 그리지 않아 입력값도 남습니다. 대신 기록할 때 1밀리초 정도 더 듭니다.

### Q2. 키프레임은 왜 10칸마다인가요? (설계 근거)

> 메모리와 점프 시간의 트레이드오프라서 재서 정했습니다. 5칸이면 43메가, 25칸이면 10메가이고, 간격이 넓을수록 멀리 이동할 때 다시 만들 칸이 늘어납니다. 10칸이면 메모리가 9분의 1이면서 50칸 점프도 예전보다 느려지지 않았습니다. 다만 화면 크기나 기록 패턴에 따라 최적값은 달라질 수 있습니다.

### Q3. 작은 배열 하나 만드는 게 왜 그렇게 비싼가요? (원리)

> 하나는 싸지만 노드 수만큼 매번 만듭니다. 1만 줄이면 다시 그릴 때마다 수만 개를 할당하고 복사하고, 나중에 쓰레기 수집이 치워야 합니다. 함수 호출마다 malloc 과 free 를 하는 것과 같아서, 재귀 깊이만큼의 배열 하나를 재사용하게 바꿨습니다. 결과는 바꾸기 전과 4만 3천 건 대조해 같습니다.

### Q4. 그래서 화면은 얼마나 빨라지나요? (실용성)

> 1,000줄에서는 diff 가 1밀리초 정도라 diff 만 줄여서는 화면이 크게 달라지지 않습니다. 화면을 빠르게 한 건 DOM 을 덜 옮긴 쪽으로 줄 하나를 위로 올릴 때 50밀리초가 24밀리초가 됐고, 히스토리는 이동할 때 diff 를 없앴습니다. diff 개선 자체는 노드가 많은 화면이나 느린 기기에서 더 드러납니다.

# 내가 짠 것처럼 말하기 — 핵심 원리 30초 멘탈 모델

> 1. **diff 지연 = 노드 수에 비례하는 일**
>    바뀐 게 한 글자여도 트리 전체를 훑습니다. 노드 하나당 하는 일이 조금만 무거워도 전체가 느려집니다.
>
> 2. **할당 제거 = malloc 대신 스택 버퍼**
>    자식마다 경로 배열을 새로 만들던 걸, 재귀 깊이만큼의 배열 하나를 덮어쓰고 패치가 생길 때만 복사하게 바꿨습니다.
>
> 3. **숨은 n 제곱 → Fenwick 트리**
>    LIS 는 누구를 옮길지만 알려 주고, 몇 번째 자리인지는 따로 셉니다. 매번 처음부터 세면 n 제곱, Fenwick 트리로 "내 앞에 몇 개?" 를 log n 에 셉니다.
>
> 4. **히스토리 = 동영상의 I-프레임 / P-프레임**
>    10칸마다 화면 전체(키프레임), 그 사이는 바뀐 부분(패치)만. 한 칸 이동은 패치를 그대로 쓰고, 멀리 갈 때만 가까운 키프레임에서 다시 만듭니다.

**외울 숫자 4개**: 할당 60% (프로파일) · 1만 줄 다시 그리기 38 → 12ms · 히스토리 메모리 207 → 23MB · 한 칸 뒤로 diff 0번
