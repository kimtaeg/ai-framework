구현의 핵심 원리와 과제의 중점 포인트를 정리한 문서입니다.

1. 구조 2. 해시 테이블 3. 동시성 문제가 생기지 않는 구조 4. 만료된 값을 요청받으면 5. 외부에서 쉽게 쓰는 API 6. 데이터 무효화 7. 서버가 다운돼도 데이터 유지 (선택) 8. 테스트 9. 한계와 개선

1. 구조

외부 프로그램→api.js (HTTP)→miniredis.js (명령)→hashtable.js→persistence.js (AOF)
  • api.js — 주소/메서드 → 명령, 입력 검사, 상태 코드. client.js 로 감싸서 쓰기 쉽게
  • miniredis.js — 명령 26가지, TTL(지연 + 주기 삭제), 태그 무효화. Node 모듈을 안 써서 브라우저에서도 그대로 실행
  • hashtable.js — FNV-1a, 체이닝, 점진적 리해시
  • persistence.js — AOF 한 줄씩, fsync 정책, 재시작 재생, 원자적 재작성

2. 해시 테이블

키를 FNV-1a 로 32비트 정수로 바꾸고 hash & (버킷 수 - 1) 로 버킷을 고릅니다. 같은 버킷은 연결 리스트로 잇고(체이닝), 부하율이 1 을 넘으면 2배 테이블을 만들어 연산마다 버킷 하나씩 옮깁니다(점진적 리해시). 옮기는 동안 조회는 두 테이블을 모두 봅니다.

Map/Object 를 저장소로 쓰지 않고 직접 구현했습니다. 테스트는 해시 함수를 () => 0 으로 바꾼 최악의 경우와 무작위 5,000번 연산을 Map 과 비교하는 퍼즈로 검증합니다.

3. 동시성 문제가 생기지 않는 구조

명령 처리를 한 스레드에서 하고, 명령 실행 함수(command())를 동기 함수로 만들었습니다. 한 요청의 명령이 실행되는 동안에는 다른 요청이 끼어들 틈이 없어서, 락이 없어도 명령 하나는 항상 원자적입니다. 여러 단계가 필요한 작업은 INCR · SET NX 처럼 한 명령으로 만들거나 /pipeline 으로 묶습니다.

테스트: 동시 INCR 200개 → 정확히 200 / GET+SET 으로 나누면 50개 중 일부를 잃음.

4. 만료된 값을 요청받으면

키마다 만료 시각(절대 시각)을 저장하고, 키를 읽는 모든 명령이 지나는 #lookup() 에서 확인해 지났으면 그 자리에서 지우고 "없음" 을 돌려줍니다(지연 삭제). 아무도 안 읽는 만료 키는 100ms 마다 TTL 키 20개를 무작위로 뽑아 지우는 주기 삭제가 치웁니다(25% 넘게 만료면 반복).

GET k→expireAt ≤ now?→삭제 + nil→아니면 값

메서드주소본문응답
GET/keys/:key—200 { key, value, ttl } · 404
PUT/keys/:key{ value, ttl?, px?, nx?, xx?, tags? }201 · 200 · 409 · 400
DELETE/keys/:key—{ deleted }
POST/keys/:key/expire · /incr{ ttl } · { by }{ updated } · { value }
GET/keys?pattern=—{ keys }
POST/invalidate{ tags?, pattern? }{ deleted }
POST/command · /pipeline{ args } · { commands }{ result } · { results }

단독 서버 npm run redis(포트 6380)는 위 주소 그대로, npm start 서버는 앞에 /api/redis 를 붙입니다.

6. 데이터 무효화

  • TTL — 자연 만료
  • DEL — 원본 수정 직후 삭제 (덮어쓰기보다 안전)
  • TAG / INVALIDATE — 이름표를 붙여 관련 키를 한꺼번에 (tag → 키 집합 색인 유지)
  • DELPATTERN — product:* 처럼 패턴으로

7. 서버가 다운돼도 데이터 유지 (선택)

쓰기가 성공할 때마다 결과를 다시 만들 수 있는 명령을 파일 끝에 한 줄씩 씁니다(AOF). TTL 은 절대 시각(PXAT), INCR 은 결과 값을 SET 으로 기록해 재생이 멱등입니다.

fsync손실속도
always0가장 느림
everysec (기본)최대 1초보통
no버퍼 크기만큼가장 빠름

재시작 때 쓰다 만 마지막 줄은 버리고, 현재 상태만 담아 임시 파일 → fsync → rename 으로 원자적으로 재작성합니다.
