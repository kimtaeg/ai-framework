3 예제별로 꼭 답해볼 질문

답을 먼저 말해본 뒤 "힌트"를 열어 확인하세요.

🔐 로그인 세션

세션을 DB 가 아니라 레디스에 두는 이유는?

요청마다 확인하니 아주 빨라야 하고, 잠깐만 있으면 되는(TTL) 데이터라서입니다. 잃어도 다시 로그인하면 되는 데이터라 메모리에 두기 좋습니다.

"페이지 이동" 이 EXPIRE 를 부르는 이유는?

쓰는 동안은 끊기지 않게 만료 시간을 다시 채우는 슬라이딩 만료입니다. 가만히 두면 TTL 이 끝나 자동으로 로그아웃됩니다.

🚦 요청 횟수 제한

동시에 요청이 몰려도 정확히 세는 이유는?

INCR 이 읽고 더하고 쓰기를 서버 안에서 한 번에 하는 원자적 명령이라서입니다. 중간에 다른 요청이 끼어들 수 없습니다.

EXPIRE 를 첫 요청에만 붙이는 이유는?

매번 붙이면 요청이 계속 오는 한 창이 끝나지 않습니다. 첫 요청에 한 번만 붙여야 "10초 창" 이 됩니다.

🔒 분산 락

락에 TTL 이 꼭 필요한 이유는?

락을 잡은 서버가 해제 전에 죽으면 아무도 지우지 않아 영원히 잠깁니다. TTL 이 있으면 저절로 풀립니다.

해제할 때 토큰을 확인하는 이유는?

작업이 TTL 보다 길어 락이 다른 워커에게 넘어간 뒤, 원래 주인이 끝나서 DEL 하면 남의 락을 지우게 됩니다.

⏳ 만료 · 🗂 해시 테이블

지연 삭제만 있으면 무엇이 문제인가?

아무도 안 읽는 만료 키가 메모리에 계속 남습니다. 그래서 주기 삭제로 표본을 뽑아 치웁니다.

리해시를 나눠서 하는 이유는?

한 번에 옮기면 원소 수만큼 걸리는 동안 모든 요청이 멈춥니다. 연산마다 버킷 하나씩 옮기면 최악의 한 번이 짧아집니다.

5 함께 쓰면 좋은 도구

터미널 (npm)

  • npm start — 모든 페이지 + /api/redis
  • npm run redis — 단독 서버 (포트 6380, AOF: week2/data/redis.aof)
  • npm test — 레디스 단위·기능 테스트 포함

curl / Playground 7

서버로 열면 Playground 7 에서 요청을 보내고 상태 코드(200/201/404/409/400)를 확인할 수 있습니다.

curl localhost:6380/keys/user:1

샌드박스

샌드박스에서 redis.exec('…') 로 원하는 명령 조합을 직접 짜서 실행하고, 오른쪽에서 키와 TTL 을 바로 확인합니다.
