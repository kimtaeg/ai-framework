스레드 풀 · 락 시뮬레이션

요청은 대기열에 줄을 서고, 쉬는 워커가 하나씩 가져갑니다. 읽기(SELECT)는 여러 워커가 함께, 쓰기(INSERT)는 혼자 합니다. 쓰기는 "① 다음 id 를 읽고 → (일하고) → ② +1 해서 저장" 하는데, 락을 끄면 두 워커가 같은 id 를 읽습니다.

해 보기① 락을 켠 채 "INSERT 4개" → 워커가 4개여도 한 번에 하나씩 처리하고 id 가 1,2,3,4 로 겹치지 않습니다. ② 락을 끄고 다시 → 4개가 동시에 같은 다음 id 를 읽어서 중복 id 가 생깁니다. ③ "섞어서" → 쓰기가 기다리는 동안 뒤의 읽기도 기다려서 쓰기가 굶지 않습니다(공정성).
실제 서버의 설계메인 스레드가 HTTP 요청을 받아 SQL 을 미리 파싱(문법 에러는 워커 없이 바로 400) → 테이블별 읽기/쓰기 락 → 쉬는 워커에 전달. 워커마다 자기 엔진(처리기 + B+ 트리)이 있어서, INSERT 가 끝나면 새 (id → 위치)를 다른 모든 워커에 알린 뒤 락을 풉니다. 워커는 메시지를 받은 순서대로 처리하므로 이후 조회는 항상 최신 인덱스를 씁니다. 여러 테이블을 잠글 때는 이름 순서로 잡아 교착 상태를 막습니다.
