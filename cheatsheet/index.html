miniReact 한 장 요약

발표 직전에 훑어보는 핵심 정리. 인쇄하면 A4 한 장에 맞춰집니다.

① 전체 흐름

클릭 → setState → (microtask 예약)
→ render: 함수 실행 → 새 VDOM
→ diff(이전, 새) → patches
→ patch: 바뀐 곳만 DOM 반영
→ useLayoutEffect → 화면 그림 → useEffect

UI = f(state): 화면은 상태의 결과. 무엇을 바꿀지는 diff 가 계산.

② 실제 DOM 이 느린 이유

  • Reflow: 크기·위치 다시 계산 (부모·형제까지 연쇄) — 가장 비쌈
  • Repaint: 색만 다시 칠함
  • Composite: transform, opacity — 제일 쌈
  • 문제는 조작 한 번이 아니라 불필요하게 자주 조작하는 것
  • 감지 API: MutationObserver (DOM 변경 기록)

③ Virtual DOM

  • 구조: { type, props, key, children } 평범한 객체
  • 왜: 선언적으로 쓰면서도 바뀐 곳만 DOM 반영
  • "DOM 보다 빠르다" ✕ — 직접 정확히 고치는 게 제일 빠름. VDOM 은 관리 비용을 줄이는 절충안
  • h() 코드→VNode, domToVNode() DOM→VNode, createElement() VNode→DOM

④ Diff 의 두 가정 → O(n)

  1. 타입(태그)이 다르면 하위 비교 없이 통째로 교체
  2. 형제 리스트는 key 로 같은 노드를 찾음

+ 같은 레벨끼리만 비교. 완벽한 비교는 O(n³).

케이스조건DOM API
INSERT새 노드insertBefore

⑥ key

  • 리스트에서 "아까 그 항목" 을 알아보는 이름표
  • index 를 key 로 ✕: 앞에 추가하면 전부 수정 + 입력값이 엉뚱한 항목에
  • 형제 사이에서만 고유하면 됨. Math.random() ✕
  • miniReact 는 LIS 로 이동 최소화: [A,B,C,D]→[B,C,D,A] 이동 1번

⑦ Patch 순서 (주소가 안 틀어지게)

  1. 삭제는 뒤에서부터
  2. 이동·추가로 자리 확정
  3. 그다음 자식 안으로 들어가 비교

path [0,2,1] = 루트 → 0번 → 2번 → 1번 자식

⑧ Hooks 원리

  • 상태는 함수 밖, 컴포넌트의 hooks 배열에
  • 렌더 전: currentComponent = this; hookIndex = 0
  • Hook 호출마다 hooks[hookIndex++] → 호출 순서가 곧 이름
  • 규칙: 최상위에서만 (조건문·반복문 ✕), React 함수 안에서만
  • 과제 제약: Hook 은 루트에서만, 자식은 props 만 (miniReact 가 에러로 강제)

⑨ setState 가 하는 4가지

  1. 새 값 계산 (함수면 이전 값 넣어 실행)
  2. 같으면(Object.is) 멈춤
  3. 칸에 저장
  4. 다시 그리기 예약 (바로 안 그림)

Batching: 여러 setState → 렌더 1번. React 18+ 는 어디서든 자동. miniReact 는 queueMicrotask 한 번만 예약.

setN(n+1)×3 = +1 (스냅샷) · setN(p=>p+1)×3 = +3

⑩ useEffect · useLayoutEffect

  • deps 생략: 매 렌더 · []: 처음 1번 · [a]: a 바뀔 때
  • cleanup: 다음 실행 직전 + 사라질 때
  • useEffect: 화면 그린 뒤 (대부분 이것)
  • useLayoutEffect: DOM 반영 직후 그리기 전 (깜빡임 방지)
  • 렌더 중에는 실행하지 않고 예약만 (렌더는 순수해야)

⑪ useMemo · useCallback · memo · useRef

  • useMemo: 계산 결과 기억 (deps 같으면 재사용)
  • useCallback: 함수 기억 = useMemo(() => fn)
  • React.memo: props 같으면 렌더 건너뜀
  • 측정 후 필요한 곳만. 남용하면 손해
  • useRef: 렌더 간 유지, 바꿔도 다시 안 그림

⑫ State 는 어디에?

  • 쓰는 컴포넌트들의 가장 가까운 공통 부모 (Lifting State Up)
  • 데이터는 아래로(props), 요청은 위로(콜백) — 단방향
  • 계산 가능한 값은 state ✕ (Single Source of Truth)
  • 불변성: push ✕ → [...list, x] ✓ (참조 비교라서)
  • 깊은 전달은 Context (createContext, useContext)

⑬ React 의 Render / Commit, Fiber

  • Render: 계산 (중단·재시작 가능, 순수해야)
  • Commit: DOM 반영 (한 번에, 중단 불가)
  • Fiber(16+): 작업을 쪼개 멈췄다 이어감 → 동시성, Suspense 기반
  • 이벤트: 루트 하나에 위임 + SyntheticEvent
