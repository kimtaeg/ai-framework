3 예제별로 꼭 답해볼 질문

답을 먼저 말해본 뒤 "힌트"를 열어 확인하세요.

🛒 장바구니

수량을 바꾸면 행 전체가 아니라 숫자만 바뀌는 이유는?

같은 key 의 같은 <li> 라서 노드를 재사용하고, 바뀐 텍스트 노드만 TEXT 패치로 고칩니다. 수량 버튼의 disabled 가 바뀌면 PROPS 도 생깁니다.

합계를 useState 로 따로 두면 어떤 버그가 생길까?

수량을 바꿀 때마다 합계도 따로 갱신해야 하고, 한 곳이라도 빠뜨리면 목록과 합계가 서로 다른 값을 보여줍니다. 계산 가능한 값은 state 가 아니라 계산값(useMemo)으로 둡니다. (Single Source of Truth)

📝 회원가입 폼

칸을 벗어날 때 테두리 색이 바뀌는 건 어떤 패치?

PROPS 입니다. <label> 의 class 가 field → field invalid 로 바뀌고, 안내 문구는 TEXT 로 바뀝니다.

가입하면 왜 REPLACE 가 될까?

루트가 <form> 에서 <div class="form-done"> 으로, 태그 종류가 바뀌기 때문입니다. 타입이 다르면 하위를 비교하지 않고 통째로 새로 만듭니다.

📋 칸반 보드

▲▼ 는 MOVE 인데 ◀▶ 는 왜 REMOVE + INSERT?

Diff 는 같은 부모 안에서만 비교합니다. 같은 열 안의 이동은 같은 <ul> 안이라 key 로 찾아 옮기지만, 다른 열은 다른 <ul> 이라 한쪽에서 지우고 다른 쪽에 새로 만듭니다.

카드에 key 가 없었다면 ▲▼ 결과는?

순서(위치)로 짝을 지어서, 두 카드의 노드는 제자리에 두고 안의 제목 텍스트와 data-id 를 서로 바꿔 씁니다. MOVE 대신 TEXT 와 PROPS 가 여러 개 생깁니다.

📊 1,000행 리스트

검색어를 지우면 왜 INSERT 가 수백 개 생길까?

검색 중에 맞지 않아 REMOVE 됐던 행들이 다시 목록에 돌아오기 때문입니다. 남아 있던 행은 key 로 재사용됩니다.

"점수 높은 순"에서 점수를 올리면 왜 MOVE 가 생길까?

점수가 바뀌면 정렬 순서가 바뀌어 그 행이 위로 올라갑니다. key 가 같으니 새로 만들지 않고 기존 <tr> 을 옮깁니다.

⏱ 스톱워치

초당 30번 넘게 렌더링되는데 왜 버벅이지 않을까?

렌더링(함수 실행 + 비교)은 가벼운 JS 계산이고, 실제 DOM 은 시간 텍스트 하나만 바뀌기 때문입니다. 렌더링 ≠ DOM 다시 그리기.

누적 시간을 useRef 에 둔 이유는?

화면에 직접 보여주는 값이 아니라 계산용 값이라, 바꿀 때마다 다시 그릴 필요가 없습니다. useRef 는 렌더 간에 유지되지만 바꿔도 리렌더링을 일으키지 않습니다.
