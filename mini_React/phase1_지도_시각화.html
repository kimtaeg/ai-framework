1. 먼저 결론

한 줄 답: 이 페이지는 엔진 함수가 DOM을 VNode로 적어 두고(domToVnode), diff 함수가 이전·새 VNode의 차이만 실제 영역 DOM에 반영하며, 호스트 코드가 반영된 VNode를 history 배열에 쌓아 되돌려요.

왜 DOM을 바로 비교하지 않고 VNode를 거치나?

  1. DOM 두 개를 견주려면 화면에 붙은 무거운 노드를 계속 읽어야 해요.
  2. VNode는 JS 객체라서 history에 여러 시점을 그대로 보관할 수 있어요(phase1_playground.html 140행 let history = [currentVNode]).
  3. 그래서 뒤로가기는 보관된 VNode를 꺼내 diff에 넘기는 일 하나로 끝나요(231~250행 travel).

상태: 위 세 줄의 근거 파일·행은 직접 읽어 확인했어요. "VNode 쪽이 더 빠르다"는 속도 주장은 이 페이지에서 측정하지 않았어요(미확인).

한계 1 — 최상위 요소가 여러 개여도 첫 번째만 처리한다




항목내용


현상테스트 영역에 최상위 요소를 2개 이상 두고 Patch를 눌러도, 둘째 요소 이후는 읽지 않아 "변경 없음"으로 끝난다. 코드 확인 + 측정: 3절 "최상위 2개 만들기" 버튼이 이 결과를 낸다.


재현 입력테스트 영역 끝에 <p>둘째</p>를 추가한 뒤 Patch.


원인 줄phase1_playground.html 190~193행: testSurface.firstElementChild ? domToVnode(testSurface.firstElementChild) : null. 실제 영역도 actualRoot = actualSurface.firstElementChild(143행)로 첫 요소 하나만 추적한다.


기대 동작과제는 "현재 테스트 영역 상태를 다시 Virtual DOM으로 만든다"고 요구한다. 상태의 단위는 첫 요소가 아니라 영역 전체다.


수정 지시① 영역의 모든 최상위 요소를 VNode 배열로 변환하는 함수를 만든다(domToVnodeList(container)). ② history의 한 칸은 이 배열 전체로 한다. ③ 영역 단위 diff 함수를 만들어, 배열의 같은 위치끼리 기존 diff를 부르고 남는 쪽은 추가 · 삭제한다. ④ 최상위 요소가 0개인 상태(빈 영역)도 유효한 상태로 처리한다.


완료 조건(a) 둘째 요소를 추가한 Patch 뒤 실제 영역에 최상위 요소가 2개이고 실제.innerHTML === 테스트.innerHTML이다. (b) 이 Patch로 history.length가 1만큼 늘고, 뒤로가기로 1개짜리 상태가 돌아온다. (c) 영역을 비우고 Patch해도 예외가 없고 실제 영역도 비워진다.









한계 2 — 자식을 위치(index)로만 비교한다 (key 없음)




항목내용


현상측정: <li> 4개 A B C D에서 맨 앞 A를 지우면 결과 DOM은 맞지만 MutationObserver 기록이 4건이다(필요한 최소는 1건). 맨 앞에 A를 끼워 넣는 경우도 4건이다. 위치 0·1·2의 글자를 모두 덮어쓰고 마지막 하나를 지우기 때문이다.


재현 입력1) ul에 li A B C D를 두고 A만 삭제 후 Patch. 2) A B C를 B A C로 순서만 바꾸고 Patch(노드가 재사용되지 않고 글자만 덮어써진다는 점은 코드 확인).


원인 줄diff.js 110~114행: for (i = 0; i < count; i += 1) diff(currentDom, domChildren[i], oldChildren[i], newChildren[i]). 같은 위치(i)의 두 자식만 짝지으며 식별자를 보지 않는다.


기대 동작과제의 중점 포인트는 "최소 변경을 찾기 위한 5가지 핵심 케이스"다. key 지원은 과제에 명시된 의무가 아니므로 선택 구현으로 지시한다. 단 key가 없는 기존 동작은 그대로 유지해야 한다.


수정 지시① 자식 VNode의 props.key를 식별자로 허용하고, domToVnode가 key 속성을 읽어 VNode에 담게 한다. ② 자식을 비교할 때 key가 있으면 같은 key끼리 짝지어 diff를 부르고, 순서가 다르면 insertBefore로 DOM 노드를 옮긴다. ③ key가 없는 자식은 지금처럼 위치로 비교한다. ④ key는 DOM 속성으로 렌더링하지 않는다.


완료 조건(a) key 있는 li A B C D에서 A 삭제 시 MutationObserver 기록이 1건이다. (b) A B C를 B A C로 바꿀 때 li DOM 노드 3개의 참조(===)가 Patch 전후 같다. (c) key 없는 기존 테스트는 결과가 그대로다.









한계 3 — 자식을 2개 이상 지우면 예외가 나고 실제 영역이 망가진다




항목내용


현상측정: li 4개 A B C D를 A B로 줄이면 TypeError: Failed to execute 'removeChild' ... parameter 1 is not of type 'Node'가 난다. 예외 뒤 실제 DOM은 기대한 A B가 아니라 A B D로 남는다. A B → 빈 ul도 같은 예외가 나고 B가 남는다. 마지막 1개만 지우는 경우는 성공한다(측정, 손댄 노드 1건).


재현 입력3절 "자식 2개 삭제 (한계 시연)" 버튼, 또는 ul의 li를 2개 이상 지우고 Patch.


원인 줄diff.js 109행 const domChildren = childNodes(currentDom)가 살아 있는 목록(live NodeList)을 그대로 들고 있다(코드 확인). 112~114행 루프에서 i = 2의 삭제(84행 parentDom.removeChild)가 목록을 즉시 줄이면, i = 3의 domChildren[3]은 undefined가 된다(측정으로 일치 확인).


기대 동작과제의 품질 항목은 "엣지 케이스를 최대한 고려한다"이고, 5가지 핵심 케이스에는 노드 삭제가 들어 있다. 삭제 수와 무관하게 결과가 같아야 하고, 실패하더라도 화면과 history가 어긋나면 안 된다.


수정 지시① 자식 루프 전에 Array.from(currentDom.childNodes)로 스냅샷을 만들어 그 배열만 인덱싱한다. ② 공통 길이까지는 위치별로 diff를 부르고, old가 더 길면 초과 자식을 뒤에서 앞으로 제거한다. ③ patchFromTestArea는 diff를 try/catch로 감싸고, 예외가 나면 history와 currentVNode를 바꾸지 않은 채 실제 영역을 currentVNode로 다시 그려 복구한다(3절 데모가 이미 하는 복구와 같은 방식). ④ 복구가 일어났음을 status에 표시한다.


완료 조건(a) A B C D → A B, A B C D → 빈 ul, A B C → A 세 경우 모두 예외 0이고 실제.innerHTML === 기대 HTML이다. (b) 각 경우 MutationObserver 기록 수가 지운 노드 수와 같다. (c) 강제로 예외를 낸 경우에도 history.length와 historyIndex가 Patch 전과 같다.

4. 판정은 결과 DOM과 손댄 노드 수(MutationObserver 기록 수) 둘 다로 한다.

[수정 1 — 필수, 최우선] 자식을 2개 이상 지우면 예외가 난다.
- 현상: ul의 li A,B,C,D를 A,B로 줄이면 TypeError(removeChild)가 나고 실제 DOM이 A,B,D로 남는다. A,B를 빈 ul로 줄여도 예외가 난다.
- 원인: diff.js 109행이 살아 있는 childNodes를 그대로 쓰고, 112~114행 루프 중 삭제가 목록을 줄여 domChildren[i]가 undefined가 된다.
- 지시: 루프 전에 Array.from(currentDom.childNodes)로 스냅샷을 만든다. 공통 길이까지 위치별 diff, old가 더 길면 초과분을 뒤에서 앞으로 제거한다. patchFromTestArea는 diff를 try/catch로 감싸 예외 시 history와 currentVNode를 바꾸지 않고 실제 영역을 currentVNode로 다시 그린 뒤 status에 복구 사실을 표시한다.
- 완료: A B C D→A B, A B C D→빈 ul, A B C→A 모두 예외 0, 실제.innerHTML === 기대 HTML, MutationObserver 기록 수 = 지운 노드 수. 예외를 강제로 내도 history.length와 historyIndex가 Patch 전과 같다.

[수정 2 — 필수] 최상위 요소가 여러 개여도 첫 번째만 처리한다.
- 현상: 테스트 영역에 최상위 요소를 둘 두고 Patch하면 "변경 없음"으로 끝난다.
- 원인: phase1_playground.html 190~193행의 testSurface.firstElementChild, 143행의 actualRoot = actualSurface.firstElementChild.
- 지시: 영역의 모든 최상위 요소를 VNode 배열로 바꾸는 domToVnodeList(container)를 만들고, history 한 칸을 이 배열 전체로 한다. 배열 위치별로 기존 diff를 부르고 남는 쪽은 추가 또는 삭제한다. 최상위 0개(빈 영역)도 유효한 상태로 처리한다.
- 완료: 둘째 요소 추가 Patch 뒤 실제 영역 최상위 요소 2개, 실제.innerHTML === 테스트.innerHTML, history.length가 1만큼 증가, 뒤로가기 시 1개짜리 상태 복원. 영역을 비워 Patch해도 예외 0.

[수정 3 — 선택, 마지막] 자식을 위치로만 비교한다(key 없음).
- 현상: li A,B,C,D에서 A만 지워도 MutationObserver 기록이 4건이다(최소 1건).
- 원인: diff.js 110~114행의 위치(i) 기준 짝짓기.
- 지시: props.key를 식별자로 허용하고 domToVnode가 key 속성을 VNode에 담게 한다. key가 있는 자식은 같은 key끼리 diff하고 순서가 다르면 insertBefore로 노드를 옮긴다. key가 없는 자식은 지금처럼 위치로 비교한다. key는 DOM 속성으로 렌더링하지 않는다.
- 완료: key 있는 li A,B,C,D에서 A 삭제 시 기록 1건. A,B,C→B,A,C 때 li DOM 노드 3개의 참조가 Patch 전후 같다. key 없는 기존 테스트 결과는 그대로다.

[보고 형식] 수정마다 (1) 바꾼 파일과 줄, (2) 추가한 테스트 이름, (3) 완료 조건 각 항목의 실제 측정값을 표로 적는다. 측정하지 않은 항목은 "미측정"이라고 쓴다.
